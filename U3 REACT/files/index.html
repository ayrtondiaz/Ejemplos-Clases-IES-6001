¿Por Qué React? — El #1 del Mundo

Componentes · Virtual DOM · Mercado Laboral

🧩

Componentes

Tu UI se divide en piezas independientes y reutilizables. Un botón, una tarjeta, un navbar... todo es un componente.

⚡

Virtual DOM

React mantiene una copia virtual del DOM. Cuando algo cambia, actualiza SOLO lo que cambió. Rendimiento excelente.

📈

Mercado Laboral

Netflix, Airbnb, Instagram, WhatsApp Web lo usan. 40% de los devs web usan React (Stack Overflow 2024).

🎯 Concepto clave React es una LIBRERÍA (no un framework completo). Se ocupa solo de la UI. Para routing y estado global se agregan librerías extras.
Clase 17 · Slide 4

JavaScript Vanilla vs React

En JS vanilla vos manejás el DOM. En React, describís QUÉ querés ver.

❌ JS Vanilla (lo que hacías)

JavaScript 
// Vos decís CÓMO actualizar el DOM
const titulo = document.querySelector("h1");
titulo.textContent = "Nuevo título";

const card = document.createElement("div");
card.innerHTML = `<h3>${nombre}</h3>`;
container.appendChild(card);

btn.addEventListener("click", () => {
  contador++;
  span.textContent = contador;
});

Vos decís CÓMO actualizar. Cada cambio = manipular el DOM manualmente.

✅ React (lo que harás)

JSX (React) 
// Vos describís QUÉ se ve
function App() {
  const [contador, setContador] = useState(0);

  return (
    <div>
      <h1>Contador: {contador}</h1>
      <button onClick={() => setContador(contador + 1)}>
        +1
      </button>
    </div>
  );
}

Vos describís QUÉ se ve. React se encarga del CÓMO.

🎯 Importante En React NUNCA vas a usar document.querySelector ni innerHTML. Todo se maneja con estado y JSX.

JSX — HTML Dentro de JavaScript

Parece HTML, pero es JavaScript. Las diferencias clave que tenés que memorizar.

Ejemplo completo de JSX

JSX (React) 
function MiComponente() {
  const nombre = "Ana";
  const edad = 22;

  return (
    <div className="tarjeta">
      <h1>Hola, {nombre}</h1>
      <p>Edad: {edad} años</p>
      <p>2 + 2 = {2 + 2}</p>
      <img src="foto.jpg" alt="Foto" />
      <label htmlFor="email">Email:</label>
    </div>
  );
}

⚠️ Diferencias HTML → JSX (memorizar)

HTML → JSX (React) ¿Por qué?
class="nombre" → className="nombre" class es palabra reservada en JS
for="email" → htmlFor="email" for es palabra reservada en JS
<img src="..."> → <img src="..." /> Todas las etiquetas se cierran
<br> <hr> <input> → <br /> <hr /> <input /> Autoclose obligatorio
<!-- comentario --> → {/* comentario */} Comentarios con llaves
style="color: red" → style={{ color: "red" }} Objeto JS, camelCase
Múltiples raíces → <>...</> (Fragment) Un solo elemento raíz
🎯 Regla Siempre retornar UN solo elemento raíz. Si necesitás varios, usá Fragment: <>...</>

Crear Componentes Funcionales

1 componente = 1 archivo · PascalCase · export default · import

Crear un componente (Header.jsx)

src/components/Header.jsx 
function Header() {
  return (
    <header className="header">
      <h1>Mi Aplicación React</h1>
      <nav>
        <a href="#inicio">Inicio</a>
        <a href="#about">About</a>
      </nav>
    </header>
  );
}

export default Header;

Usar el componente (App.jsx)

src/App.jsx 
import Header from "./components/Header";
import Footer from "./components/Footer";

function App() {
  return (
    <>
      <Header />
      <main>
        <p>Contenido principal</p>
      </main>
      <Footer />
    </>
  );
}

export default App;

Props — Pasar Datos de Padre a Hijo

El padre envía datos como atributos · El hijo los recibe con destructuring

Componente que RECIBE props

src/components/Tarjeta.jsx 
function Tarjeta({ titulo, descripcion, precio }) {
  return (
    <article className="card">
      <h3>{titulo}</h3>
      <p>{descripcion}</p>
      <span className="precio">${precio}</span>
    </article>
  );
}

export default Tarjeta;

El padre ENVÍA los datos

src/App.jsx 
import Tarjeta from "./components/Tarjeta";

function App() {
  return (
    <section className="cards">
      <Tarjeta
        titulo="Desarrollo Web"
        descripcion="Sitios modernos."
        precio={1500}
      />
      <Tarjeta
        titulo="Diseño UI/UX"
        descripcion="Interfaces intuitivas."
        precio={2000}
      />
    </section>
  );
}

Clase 18 · Slide 5

Props por Defecto + children

Valores por defecto · children: contenido entre etiquetas

Props con valores por defecto

JSX 
function Boton({ texto = "Click aquí", color = "blue" }) {
  return (
    <button style={{
      backgroundColor: color,
      color: "white"
    }}>
      {texto}
    </button>
  );
}

// Uso:
<Boton texto="Enviar" color="green" />
<Boton />  {/* Usa defaults: "Click aquí", "blue" */}

Resultado:

← Mismo componente <Boton /> con distintas props

children — Contenido entre etiquetas

JSX 
function Card({ titulo, children }) {
  return (
    <div className="card">
      <h3>{titulo}</h3>
      <div className="card-body">
        {children}
      </div>
    </div>
  );
}

// Uso: lo que ponés ENTRE las etiquetas = children
<Card titulo="Mi Card">
  <p>Este párrafo es el children.</p>
  <button>Y este botón también.</button>
</Card>

Resultado:

Mi Card ← prop titulo

Este párrafo es el children. ← children

🎯 Patrón children es una prop especial que contiene todo lo que ponés ENTRE las etiquetas. Muy usado para layouts y wrappers.

function Card({ emoji, titulo, descripcion, children }) {

    </article>
  );
}
export default Card;
src/components/Footer.jsx 
function Footer({ texto = "© 2026 Mi App" }) {
  return (
    <footer className="footer">
      <p>{texto}</p>
    </footer>
  );
}
export default Footer;
